# Component Structure Reference

Detailed file-by-file breakdown of a Convex component.

## Directory Structure

```
my-convex-component/
├── package.json           # Package metadata and entry points
├── tsconfig.json         # TypeScript configuration
├── README.md             # Component documentation
├── PUBLISHING.md         # Publishing instructions
├── src/
│   ├── test.ts           # Test helpers for @your/package/test
│   ├── client/
│   │   └── index.ts     # Client code and utilities for app-level use
│   └── component/
│       ├── _generated/    # Auto-generated by convex codegen
│       │   ├── server.js     # Function builders (query, mutation, action)
│       │   ├── api.js        # Component's api and internal objects
│       │   ├── dataModel.js  # Types for the component's data model
│       │   └── component.js  # ComponentApi type (only for components)
│       ├── convex.config.ts   # Component definition and child components
│       ├── schema.ts          # Component schema
│       ├── http.ts            # HTTP routes (optional)
│       └── *.ts               # Queries, mutations, actions
└── dist/                 # Built files for npm publishing
    ├── convex.config.js
    ├── _generated/
    │   └── component.js   # ComponentApi type export
    └── ...
```

## File Details

### package.json

Defines the package metadata, entry points, and build scripts.

```json
{
  "name": "@your/package",
  "version": "1.0.0",
  "description": "A reusable Convex component",
  "type": "module",
  "exports": {
    ".": {
      "types": "./dist/client/index.d.ts",
      "default": "./dist/client/index.js"
    },
    "./convex.config.js": "./dist/convex.config.js",
    "./_generated/component.js": "./dist/_generated/component.js",
    "./test": "./src/test.ts"
  },
  "files": [
    "dist",
    "src/test.ts"
  ],
  "scripts": {
    "build": "tsc",
    "dev": "npm run build -- --watch",
    "prepublishOnly": "npm run build"
  },
  "peerDependencies": {
    "convex": "^1.17.0"
  },
  "devDependencies": {
    "convex": "^1.17.0",
    "typescript": "^5.0.0"
  },
  "keywords": [
    "convex",
    "component"
  ]
}
```

**Note:** The `files` array includes both `dist` (the built files) and `src/test.ts` (exposed via the `./test` export). This allows npm to publish the necessary files while keeping the test helper accessible.

### src/component/schema.ts

Defines the component's database schema.

```typescript
import { defineSchema, defineTable } from "convex/server";
import { v } from "convex/values";

export default defineSchema({
  items: defineTable({
    name: v.string(),
    data: v.any(),
    createdAt: v.number(),
  }).index("by_name", ["name"]),

  config: defineTable({
    key: v.string(),
    value: v.any(),
  }).index("by_key", ["key"]),
});
```

### src/component/createItem.ts (example mutation)

Example mutation function.

```typescript
import { v } from "convex/values";
import { mutation } from "./_generated/server.js";

export const create = mutation({
  args: {
    name: v.string(),
    data: v.any(),
  },
  returns: v.id("items"),
  handler: async (ctx, args) => {
    return await ctx.db.insert("items", {
      name: args.name,
      data: args.data,
      createdAt: Date.now(),
    });
  },
});

export const update = mutation({
  args: {
    id: v.id("items"),
    data: v.any(),
  },
  returns: v.null(),
  handler: async (ctx, args) => {
    await ctx.db.patch(args.id, { data: args.data });
    return null;
  },
});

export const remove = mutation({
  args: { id: v.id("items") },
  returns: v.null(),
  handler: async (ctx, args) => {
    await ctx.db.delete(args.id);
    return null;
  },
});
```

### src/component/list.ts (example query with pagination)

Example query function.

```typescript
import { v } from "convex/values";
import { query } from "./_generated/server.js";

export const list = query({
  args: {
    limit: v.optional(v.number()),
  },
  returns: v.array(v.object({
    _id: v.id("items"),
    name: v.string(),
    data: v.any(),
    createdAt: v.number(),
  })),
  handler: async (ctx, args) => {
    return await ctx.db
      .query("items")
      .order("desc")
      .take(args.limit ?? 10);
  },
});

export const get = query({
  args: { name: v.string() },
  returns: v.union(v.object({
    _id: v.id("items"),
    name: v.string(),
    data: v.any(),
  }), v.null()),
  handler: async (ctx, args) => {
    return await ctx.db
      .query("items")
      .withIndex("by_name", (q) => q.eq("name", args.name))
      .unique();
  },
});
```

### src/component/http.ts (HTTP routes, optional)

HTTP routes defined by the component.

```typescript
import { httpRouter } from "convex/server";
import { httpAction } from "./_generated/server";

const http = httpRouter();

http.route({
  path: "/hello",
  method: "GET",
  handler: httpAction(async () => {
    return new Response("hello from component", { status: 200 });
  }),
});

export default http;
```

If your component has child components that define HTTP routes, you can mount them with their own `httpPrefix`:

```typescript
// src/component/convex.config.ts
import { defineComponent } from "convex/server";
import childComponent from "../childComponent/convex.config.js";

const component = defineComponent("myComponent");

component.use(childComponent, { httpPrefix: "/child/" });

export default component;
```

Within a component's HTTP action, `process.env.CONVEX_SITE_URL` reflects the full URL where the component is mounted, including the `httpPrefix`.

**Limitation:** Component HTTP actions do not have access to `ctx.auth` or the app's environment variables. If an HTTP handler needs to authenticate users or access data from the application, define the HTTP action handler in the component's client code and mount it in the app's `convex/http.ts` instead. There's an example of this pattern in the [Twilio component](https://github.com/get-convex/twilio).

### src/test.ts

Test helpers for `convex-test`.

```typescript
/// <reference types="vite/client" />

import type { TestConvex } from "convex-test";
import type { GenericSchema, SchemaDefinition } from "convex/server";
import schema from "./component/schema.js";

const modules = import.meta.glob("./component/**/*.ts");

/**
 * Register the component with the test convex instance.
 * @param t - The test convex instance, e.g. from calling `convexTest`.
 * @param name - The name of the component, as registered in convex.config.ts.
 */
export function register(
  t: TestConvex<SchemaDefinition<GenericSchema, boolean>>,
  name: string = "myComponent",
) {
  t.registerComponent(name, schema, modules);
}

export default { register, schema, modules };
```

This is exposed as `@your/package/test` in the package's `package.json`.

### src/client/index.ts

Client code and utilities for app-level integration. This file exports functions, classes, or utilities that apps can use to interact with the component from their own code.

Examples:
- Simple function wrappers
- API re-mounting functions
- Class-based clients

See `references/client-code-patterns.md` for detailed examples.

### dist/

Built files for npm publishing. This directory is created by `npm run build` (typically `tsc`). The key files are:

- `convex.config.js` - The component's configuration
- `_generated/component.js` - The ComponentApi type export

## Generated Files

### _generated/server.js

Contains function builders (`query`, `mutation`, `action`) for defining the component's API. It's important that you import these when defining your component's functions.

```typescript
import { query } from "./_generated/server.js";
```

### _generated/api.js

Contains the component's `api` and `internal` objects to reference the component's functions. Also includes the `components` object with references to its child components, if any.

**Note:** In general, no code outside of the component should import from this file. Instead, they should use their own `components` object which includes this component keyed by whatever name they chose to install it with.

### _generated/dataModel.js

Contains the types for the component's data model.

**Note:** The `Id` and `Doc` types here are not useful outside of the component, since the API turns all ID types into strings at the boundary.

### _generated/component.js

Only generated for components, contains the component's `ComponentApi` type. This is the only generated file that code outside the component should import.

## Key Differences from Regular Convex Development

### The Component API

When you access a component reference like `components.foo`, you're working with the `ComponentApi` type:

- **Only public functions are accessible**: Internal functions are not exposed to the parent app
- **Functions become internal references**: The component's "public" queries, mutations, and actions are turned into references with "internal" visibility. They can be called with `ctx.runQuery`, `ctx.runMutation`, etc. but **not** directly accessible from clients via HTTP or WebSockets.
- **IDs become strings**: Any `Id<"tableName">` arguments or return values become plain strings in the `ComponentApi`.

Similar to regular Convex functions, you can call both public and internal functions via `npx convex run` and the Convex dashboard.

### `Id` Types and Validation

All `Id<"table_name">` types within a component become simple string types outside of the component (in the `ComponentApi` type).

In addition, you cannot currently have a `v.id("table_name")` validator that represents a table in another component / app. For this reason, all `Id` types in the `ComponentApi` become simple strings.

### Environment Variables

The component's functions are isolated from the app's environment variables, so they cannot access `process.env`. Instead, you can pass environment variables as arguments to the component's functions.

```typescript
return await ctx.runAction(components.sampleComponent.lib.translate, {
  baseUrl: process.env.BASE_URL,
  ...otherArgs,
});
```

### Authentication via ctx.auth

Within a component, `ctx.auth` is not available. You typically will do authentication in the app, then pass around identifiers like `userId` or other identifying information to the component.

```typescript
import { getAuthUserId } from "@convex-dev/auth/server";

export const someMutation = mutation({
  args: {},
  handler: async (ctx) => {
    const userId = await getAuthUserId(ctx);
    await ctx.runMutation(components.myComponent.foo.bar, {
      userId,
      ...otherArgs,
    });
  },
});
```

### Pagination

The built-in `.paginate()` doesn't work in components, because of how Convex keeps track of reactive pagination. Therefore we recommend you use `paginator` from [`convex-helpers`](https://npmjs.com/package/convex-helpers) if you need pagination within your component.

```typescript
import { paginator } from "convex-helpers/server/paginate";

export const listPaginated = query({
  args: {
    paginationOpts: v.object({
      numItems: v.number(),
      cursor: v.optional(v.union(v.string(), v.null())),
    }),
  },
  handler: async (ctx, args) => {
    const results = await paginator(ctx.db.query("items"), args.paginationOpts);
    return results;
  },
});
```

If you expose a pagination API that wants to be used with `usePaginatedQuery`, in a React context, use the `usePaginatedQuery` from `convex-helpers` instead of the default one from `convex/react`. It will have a fixed first page size until you hit "load more," at which point the first page will grow if anything before the second page is added.

**Real-world example:** [RAG component pagination](https://github.com/get-convex/rag/blob/23fb22d593682e23d9134304e823f7532cbc7e67/src/component/chunks.ts#L437-L462)
